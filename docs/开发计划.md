| 项 | 结论 |
|---|---|
| MVP 工作量 | 约 **40 人日**（含自测，不含 P1 片段） |

## 2. M0 — 工程骨架与基础设施（5 人日）

**目标**：一条能跑通的空壳链路 —— 前端点按钮 → Rust Command → SQLite 读写 → 事件回传，且 CI 三平台构建绿。

### 任务

- [ ] **仓库与工程结构**
  - `pnpm create tauri-app` 起 Tauri 2 + React + TS，前端目录 `src/`，Rust 在 `src-tauri/`
  - 目录严格按需求 4.4 落地：`commands/ ssh/ sftp/ snippets/ storage/ crypto/ monitor/ events/`
  - `rust-toolchain.toml` 锁 Rust 版本；提交 `Cargo.lock` 与 `pnpm-lock.yaml`
- [ ] **Rust 依赖选型落地**（用 `cargo add` 拉最新兼容版后锁版本，不要手抄版本号）
  - `tokio`（full，含 rt-multi-thread / sync / time / io-util）
  - `russh` + `russh-sftp`、`rusqlite`(bundled) + `r2d2_sqlite`、`argon2`、`aes-gcm`、`rand`、`keyring`、`tracing` + `tracing-subscriber`、`thiserror`、`serde`/`serde_json`、`uuid`、`dashmap`、`tokio-util`(CancellationToken)、`encoding_rs` 或自写 UTF-8 解码器
  - release profile 加 `lto = "fat"`、`codegen-units = 1`、`opt-level = "s"`、`strip = true`（为 <20MB 服务）
- [ ] **统一错误类型** `error.rs`
  - `AppError` 枚举 → 序列化为 `{ code, message, detail? }`；`code` 用 §6 的错误码表
  - 实现 `impl From<russh::Error>` 等，把底层错误**翻译**成用户可读项，原始 error 只进 `detail`（且脱敏）
- [ ] **日志与脱敏** `logging.rs`
  - `tracing-subscriber` + 自定义 `Layer` 做字段脱敏：key 命中 `password|passphrase|secret|key|token|authorization` 时替换为 `***`
  - 日志落 `app_log_dir`，滚动保留 7 天
- [ ] **存储层** `storage/`
  - rusqlite + r2d2 连接池；所有 DB 调用走 `tokio::task::spawn_blocking`（rusqlite 是同步库，禁止在 async 上下文直接调用）
  - 迁移：`user_version` pragma + `migrations/001_init.sql`，启动时按序执行（见 §5 DDL）
- [ ] **加密层** `crypto/`
  - `KeyProvider` trait 双实现：`KeychainKeyProvider`（MVP 默认，随机 32B 数据密钥存系统钥匙串）与 `MasterPasswordKeyProvider`（Argon2id，S-05 用）
  - `encrypt(plaintext) -> Vec<u8>`（`nonce(12) || ciphertext||tag`）、`decrypt(blob)`
  - 单元测试：往返、篡改后解密失败、nonce 不复用（同明文两次密文不同）
- [ ] **IPC 骨架**
  - 一个 `ping` Command + 一个 Channel 推送 demo（前端能收到递增计数）
  - 前端建 `lib/ipc.ts` 统一封装 `invoke`，统一 catch 错误码并映射文案
- [ ] **CI**
  - GitHub Actions matrix：`windows-latest` / `macos-latest` / `ubuntu-22.04`
  - job：`cargo fmt --check`、`cargo clippy -D warnings`、`cargo test`、`pnpm lint`、`pnpm tsc --noEmit`、`tauri build`
  - Linux 需装 `libwebkit2gtk-4.1-dev` 等系统依赖
- [ ] **前端基础**
  - 路由/布局：左侧连接列表、主区 Tab 容器、底部状态栏；4 个占位页
  - Zustand store 分两个：`useSessionStore`（会话/终端状态）、`useUiStore`（面板、主题）—— 需求 4.6 要求分离

**验收**：三平台 CI 全绿；`ping` 打通；DB 迁移可重复执行；`cargo test` 含加密单测通过。

## 3. M1 — 连接管理 + 安全存储（7 人日）

### 任务

- [ ] **数据访问层** `storage/connections.rs`：CRUD + 搜索（`name LIKE ?` / host）
- [ ] **Command**（见 §6 契约）：`connection_create / update / delete / list / get / test`
  - `connection_test`：只做 TCP + 握手 + 认证，不建 shell，返回耗时与协商到的算法（用于排查兼容性问题，这个返回值在工单里非常有用）
- [ ] **认证分支**
  - 密码：表单 → Rust 加密 → `secret_blob`
  - 私钥：`key_path` 存路径；`russh::keys::load_secret_key(path, passphrase)`；加密私钥需要 passphrase，表单要能填并加密存 `key_pass_blob`
  - **注意**：需求 C-03 只写了"选择私钥文件"，漏了"加密私钥的 passphrase"——必须有，否则带密码的 id_rsa 直接登不上
- [ ] **指纹校验（SEC-04）**：实现 `client::Handler::check_server_key`
  - 首次：`known_hosts` 无记录 → 回传前端弹"未知主机指纹"确认框 → 用户确认后入库
  - 变更：指纹不匹配 → **硬失败** `SSH_HOST_KEY_MISMATCH`，不允许静默覆盖，需用户显式删除记录
  - 指纹格式统一 `SHA256:base64(nopad)`，与 OpenSSH 一致，方便用户比对
- [ ] **前端**：连接列表、新建/编辑表单（含认证方式切换）、删除二次确认、搜索框、连接测试按钮
- [ ] **快捷连接（C-07，P1）**：解析 `user@host -p port`，可顺手做，成本低

**验收**：新建 → 连接测试通过 → 重启软件仍存在 → 删除后消失；SQLite 里 `strings` 搜不到明文密码；私钥登录（含 passphrase）可用；指纹首次确认、篡改后拒绝。

## 4. M2 — SSH 终端（10 人日，**最难的一段**）

### 4.1 会话管理 `ssh/session.rs`

- [ ] `SessionManager { map: DashMap<SessionId, SessionHandle> }`，`SessionId` 由 Rust 生成（UUIDv7）
- [ ] `SessionHandle` 内含：
  - `write_tx: mpsc::Sender<InputCmd>`（输入 / resize / close 统一走这一条队列，保证顺序）
  - `cancel: CancellationToken`
  - `task: JoinHandle<()>`
- [ ] 每个会话一个独立 Tokio task，`tokio::spawn` 外层套 `catch_unwind`（A-10 崩溃隔离），panic 时发 `ssh:state = crashed` 并清理 map
- [ ] 退出/关标签：`cancel.cancel()` → 主动 `channel.eof()` + `disconnect` → `await` task 结束 → 从 map 移除。**禁止只 abort 不清理**（会泄漏 russh 后台任务）

### 4.2 终端数据流（M2 的核心）

```text
russh Channel.wait()
   → 原始 &[u8]
   → Utf8StreamDecoder（缓存尾部不完整多字节序列，等下一包补齐）
   → BatchingBuffer（攒 16ms 或 32KB，先到先发）
   → Tauri Channel<OutputBatch { seq, data: String }>
   → xterm.write(data, cb)
   → 每 50ms / 累计 256KB 回 ack(consumed_bytes)
   → Rust 侧 unacked > 2MB 时暂停 wait()（真实背压）
```

- [ ] **UTF-8 增量解码器**（自写，~60 行）：SSH 分包会把一个汉字的 3 个字节切到两个包里。用 `String::from_utf8_lossy` 会出 `�`，直接违反"中文不乱码"验收项。必须缓存 1–3 字节的尾部不完整序列
- [ ] **批量聚合**：不要每收一包就发一次 IPC。`echo` 快速滚动、`cat` 大文件时包极小极密，批量能把 IPC 次数降 1–2 个数量级
- [ ] **背压**：`data` 用 `String`（Tauri Channel 传 JSON，`Vec<u8>` 会序列化成数字数组，体积膨胀 3–5 倍，这是最容易踩的性能坑）
- [ ] **输入**：`term.onData` → `session_write(session_id, data_b64)`。输入量小，用 Command 足够，不必上 Channel（需求 4.3 写"前端通过 Channel 写入"偏复杂，建议统一为 Command，见 §9-3）

### 4.3 PTY 与窗口

- [ ] `request_pty("xterm-256color", cols, rows, ...)` → `request_shell()`
- [ ] `term.onResize` → `session_resize` → `channel.window_change(cols, rows)`（漏了会导致 `vim`/`top` 显示错乱）
- [ ] `fitAddon` 在容器尺寸变化时 `fit()`，**加防抖**（100ms），否则拖窗口会打爆 resize 事件
- [ ] 环境变量：`LANG=en_US.UTF-8` 兜底（部分容器默认 POSIX locale 会输出乱码），但**不覆盖**用户已有设置

### 4.4 前端终端

- [ ] `@xterm/xterm` 5.x + `@xterm/addon-fit` + `@xterm/addon-web-links` + `@xterm/addon-search`
- [ ] 多标签：`Map<tabId, {sessionId, term, fitAddon}>`，**切走时不要 dispose**，用 `display:none` 或离屏容器保活（dispose 会丢滚动缓冲）
- [ ] 回滚：`scrollback: 5000` 可配（T-07）
- [ ] 复制粘贴：`Ctrl/Cmd+C` 有选区时复制、无选区时发 `SIGINT`（`\x03`）——这是终端用户的肌肉记忆，做错会被骂
- [ ] 断线（T-05）：`ssh:state = disconnected` → 终端叠加半透明遮罩 + 错误码文案 + "重连"按钮；重连成功后新开会话并提示（不静默替换，避免用户以为还是原会话）
- [ ] 快捷键（T-09）：`Ctrl/Cmd+T` 新建、`Ctrl/Cmd+W` 关闭、`Ctrl+Tab` 切换；在 WebView 层 `preventDefault`，避免触发浏览器默认行为

**验收**：`ls`/`cd`/`top`/`vim` 正常；中文输入输出不乱码；`cat` 一个 50MB 日志不 OOM 不卡死；多标签切换不丢内容；断网有提示且可重连；关标签后 `session_list` 里消失、进程内存回落。

## 5. M3 — SFTP 文件管理（9 人日）

### 任务

- [ ] **连接策略**：SFTP **单独建一条 SSH 连接**（复用同一份凭据），不复用终端会话的 TCP 连接。理由：SSH 通道共享窗口，大文件传输会把终端的输出窗口饿死，表现为"传文件时终端卡住"。这是很多客户端的通病，多一条连接换来的稳定性值得
- [ ] `sftp/list.rs`：`read_dir` → 排序（目录优先）→ 带 `size / mtime / mode / uid / gid`
- [ ] **上传** `transfer/upload.rs`
  - `tokio::fs::File` 读 → 64–256KB 分块 → `sftp.write`，**流水线并发 8–16 个在途请求**（纯串行只有几 MB/s，流水线后能到几十 MB/s）
  - 远端先写 `xxx.part`，成功后 `rename`，避免半截文件（可选但强烈建议）
- [ ] **下载** 对称实现；写本地临时文件再 rename
- [ ] **进度事件**：`sftp:progress { transfer_id, transferred, total, bps }`，**150ms 节流**；别用 per-chunk 事件
- [ ] **取消**：`CancellationToken` 检查点放在每个 chunk 边界，取消后清理 `.part`
- [ ] **文件操作**：`mkdir / rename / remove`（目录递归删除需显式参数 + 前端二次确认）
- [ ] **路径安全**：所有远端路径做规范化，拒绝 `..` 越界由服务端管，但本地路径必须校验（Tauri fs 能力域限制 + 禁止写入系统目录）
- [ ] **前端**：文件面板、面包屑、双击进入目录、右键菜单、上传/下载进度条、错误 toast
- [ ] **P1 双栏**（F-09/F-10）：左本地右远程，拖拽上传。先做单栏，双栏放最后

**验收**：浏览/上传/下载/新建/重命名/删除全通；1GB 文件传完不崩、UI 可交互、可中途取消；失败有可读错误；删除有二次确认。

## 8. 第 1 周必须完成的 3 个 Spike（不通过就改方案）

> 这三个是"做不出来就得推翻技术选型"的项，必须在写业务代码前用最小 demo 验证。

| # | Spike | 验证方法 | 通过标准 | 不通过怎么办 |
|---|---|---|---|---|
| S1 | **russh 算法兼容性** | 起 3 台/3 容器：Ubuntu 24.04（新）、CentOS 7（老，`ssh-rsa`+`diffie-hellman-group14-sha1`）、一台禁用 `ssh-ed25519` 只留 RSA | 三台都能握手+密码登录 | 开 `russh::client::Config` 的 `preferred` 算法列表按需放宽；仍不行则评估 `ssh2` crate（libssh2，需 C 依赖，打包变复杂） |
| S2 | **终端吞吐与背压** | 远端 `cat` 一个 100MB 文本 / `yes` 刷屏，前端 xterm 渲染 | 无 OOM、无事件循环卡死、RSS 增长有上限、停掉前端消费后 Rust 侧会暂停读取 | 加大批量窗口（32ms/64KB）、降低 scrollback、必要时改二进制 IPC（`tauri::ipc::Response` raw bytes） |
| S3 | **中文输入与 IME** | Windows/macOS 下在终端里用中文输入法打"你好世界"，再 `echo 中文` | 无丢字、无乱序、无乱码 | 检查 xterm `onData` 是否被 IME composition 事件截断；必要时监听 `compositionend` 兜底 |

**S1/S2 的产出要写成 `docs/spike-notes.md`**，里面记下协商到的算法、实测吞吐数字，后面的兼容性工单全靠它。

### 8.1 Spike 结果回填（2026-10-28 已执行，详见 [spike-notes.md](spike-notes.md)）

| # | 结论 | 对计划的影响 |
|---|---|---|
| S1 | **风险从「高」降为「中」**。russh 默认档位连不上只有 SHA-1 的老服务器（`NoCommonAlgo { kind: Kex }`），但放宽 `Preferred` 后实测通过。**不需要换 `ssh2` crate。** | M1 增加「兼容老服务器算法」开关（约 0.5 人日） |
| S2 | **吞吐 82.4 MB/s**，慢消费者下压到 1.0 MB/s 且 RSS 只涨 5.7MB —— 背压真实生效。UTF-8 增量解码器在 2048 次分包下替换符为 0。`String` 比 `Vec<u8>` 省 **3.5×** IPC 体积。 | 终端链路设计按原方案落地，无需调整 |
| S3 | 取证工具已就绪（应用内「输入法测试」页，仅开发构建），**待三平台人工执行** | 不阻塞 M1，M2 开始前必须补完 |

额外发现一条会阻塞新机器构建的坑：`russh` 默认的 `aws-lc-rs` 在 Windows 上要求 NASM，必须加 `features = ["prebuilt-nasm"]`。

## 9. 关键技术决策（ADR）

| # | 决策点 | 建议 | 理由 |
|---|---|---|---|
| 1 | SQLite 驱动 | `rusqlite`(bundled) + `r2d2`，全部走 `spawn_blocking` | 编译快、无 async 复杂度；`sqlx` 的 async 优势在这个数据量下体现不出来 |
| 2 | 密钥存放 | MVP：随机 32B 数据密钥 → 系统钥匙串（`keyring`）；主密码模式后置 | 主密码 + Argon2id 每次启动要派生，和"冷启动 < 2s"直接冲突；`tauri-plugin-stronghold` 为 MVP 过重（带 iroh/p2p） |
| 3 | 片段/输入写入方式 | 统一用 `Command`，不用前端→Rust 的 Channel | 输入量小、需要顺序保证、调试简单；Channel 主要解决 Rust→前端的高频方向 |
| 4 | SFTP 连接 | 独立 SSH 连接 | 避免大文件传输拖慢终端通道 |
| 5 | SFTP 并发 | 8–16 个在途写请求 | 串行吞吐差一个数量级 |
| 6 | 终端 IPC 负载 | `String` + 16ms/32KB 批量 | JSON 传 `Vec<u8>` 会膨胀数倍 |
| 7 | 终端组件 | `@xterm/xterm` 5.x（新包名） | 旧的 `xterm` 包已停止更新 |
| 8 | 状态管理 | Zustand，会话态与 UI 态分离 | 需求 4.6 明确要求；Redux Toolkit 对此规模偏重 |

## 14. 对需求文档的补强建议

评审时发现的空缺，建议在 V0.4 补进去（否则实现阶段必然要临时决策）：

1. **加密私钥的 passphrase** — C-03 只写"选择私钥文件"，但 `id_rsa` 通常有口令。需增加"私钥口令"字段并加密存储。
2. **主机密钥变更的处理** — S-04 只说"首次展示指纹"，没说变更时怎么办。必须明确：**变更即阻断**，不允许静默覆盖（这是 MITM 的主要入口）。
3. **断线重连语义** — T-05 只说"支持手动重连"，未定义：重连是否复用原标签？SFTP 面板是否跟着重建？建议：复用标签、新会话、明确提示已是新会话。
4. **冷启动 < 2s 与主密码的冲突** — 若启用主密码 + 高强度 Argon2id，启动必然超 2s。建议指标拆成"冷启动（不含解锁）< 2s"。
5. **SFTP 同名文件策略** — F-03/F-04 没说覆盖、跳过还是重命名。建议 MVP 弹窗三选一，默认询问。
6. **数据库迁移策略** — 全文未提 schema 升级。首发前必须定 `user_version` 迁移机制，否则第二个版本就要用户删库。
7. **单实例与多窗口** — 未定义。建议 MVP 单实例单窗口（多标签够用），避免会话跨窗口同步的复杂度。
8. **片段"发送执行"的边界** — §5.7.3 说只读片段可"发送执行"，但 `ps aux | grep {keyword}` 若用户把 keyword 填成 `x; rm -rf /` 就是注入。必须写明：变量值做单引号包裹转义 + 拒绝换行符。
9. **终端滚动缓冲与内存** — 5000 行 × N 标签的内存上界未估算。10 个标签约 30–80MB，可接受，但应在设置里给出上限提示。
10. **监控数据来源** — M-01 未指定实现方式。建议明确"读 `/proc` 优先，不跑 `top`"，避免非交互式命令挂起。

## 17. MCP 支持（分步，2026-11-02 定）

### 17.0 要解决什么

让**智能体能通过本客户端看服务器、将来也能执行经过批准的命令**，而不必把 SSH 凭据或私钥
交给智能体的运行环境。凭据不出客户端，是这个应用存在的意义之一；MCP 是把这个边界延伸到
智能体这一侧的唯一办法。

同时明确：MCP 让客户端变成"代理"，会把智能体的权限放大到用户本人。**所以闸门比能力重要**，
能不做执行就先不做。

### 17.1 架构：独立的无头二进制，不走 IPC 桥

新增 `src/bin/termharbor-mcp.rs`，用 stdio 说 MCP，直接复用现有的 `storage` / `crypto` /
`ssh` / `sftp` 四层。

**为什么可行**：这四层**没有任何 `use tauri`**（`grep` 过），是 M2 就定下的约束
（`ssh` 层不许依赖 Tauri 类型，否则 `cargo test --lib` 会把 tao/wry 链进来）。
当时是为了能跑单测，现在正好兑现成"GUI 之外也能用"。

**为什么不选另外两条路**：

| 方案 | 为什么不选 |
|---|---|
| 应用内起本地 HTTP MCP | 要给 WebView/Tauri 权限模型开口子；且 GUI 没开就不能用 |
| stdio 代理转发给运行中的 GUI | 多一层协议 + 必须开机就打开 GUI；还得处理 single-instance |

**代价**：M8-2 的"每次执行弹窗批准"没法弹 GUI 对话框 —— 改为**规则批准**：
批准发生在配置里（哪些连接、哪些命令前缀），执行时逐条写审计日志。这比"每次点确认"弱，
但比"没有闸门"强得多，而且可审计、可回溯。

### 17.2 M8-1 只读（先做这一档）

| 工具 | 做什么 | 约束 |
|---|---|---|
| `list_connections` | 返回连接列表的**非敏感字段**（名称/主机/端口/用户） | 不含密码、不含私钥、不含指纹 |
| `server_facts` | 跑内置诊断（`monitor` 那 6 条），返回结构化结果 | 只能跑白名单里的命令，不接受任意命令 |
| `sftp_list` | 列远端目录 | 只读 |
| `read_file` | 读远端文本文件 | 只读、大小上限（256KB）、**拒绝**碰 `~/.ssh` 与客户端数据目录 |
| `load_snapshot` | CPU/内存/磁盘/网络快照 | 只读 |

验收：任意 MCP 宿主（Claude Desktop / WorkBuddy）能列出这 5 个工具，并读到一台机器上
`/etc/hostname` 的内容。**全程没有任何写操作路径可走。**

### 17.3 M8-2 受控执行

- 工具：`exec`（一次一命令，返回 stdout/stderr/退出码）
- 三道闸门：
  1. 连接必须在 `mcp.json` 里显式 `enabled`（默认全部不暴露）
  2. 命令必须匹配该连接下的 `allow_prefixes`，且不匹配 `deny_patterns`
  3. 每次执行写审计（时间、连接、完整命令、退出码、耗时、输出去向）
- 现在 `ssh/exec.rs::exec_once` 已经够用，差三样：**退出码**（`ChannelMsg::ExitStatus` 被忽略）、
  超时可配、并发上限
- 白名单的默认值应当"空"：装了不等于能用，必须用户逐条加

### 17.4 M8-3 写操作

上传/下载/chmod。默认关，且必须有"目标路径白名单"。**这一档不急，甚至可以永远不做**。

### 17.5 红线（任何一档都不许越）

- 不返回密码、私钥、`known_hosts` 指纹
- 不提供"修改连接/修改设置"的接口
- 不提供任意本地路径读写、不提供"打开任意 URL"
- 不接受智能体传来的 shell 复合命令（`;` / `&&` / 管道）—— 那等于给了半个 shell

### 17.6 工程细节

- **协议**：JSON-RPC 2.0 over stdio（换行分隔）。M8-1 只需要 `initialize`、`tools/list`、
  `tools/call` 三个方法。**先不引 `rmcp`**：它的 API 还在快速变化，而我们只要三个方法，
  手写分发约 300 行，且能单测（喂 JSON 行 → 断言响应）。
- **路径解析**：`state.rs::AppPaths::resolve` 现在依赖 `AppHandle`，要加一个不依赖 Tauri 的
  `resolve_headless()`（Windows 用 `%APPDATA%\com.termharbor.app`）。这是唯一的 Tauri 耦合点。
- **数据库并发**：GUI 与 MCP 会同时开同一个 SQLite（WAL）。两边都只读业务数据；
  MCP 的审计写**独立的日志文件**，不写库，避免抢写锁。
- **配置**：`%APPDATA%\TermHarbor\mcp.json`（哪些连接暴露、允许的命令前缀、输出上限）。
  放产品名目录而不是 `com.termharbor.app`，理由同快照（卸载器会删后者）。
- **密钥**：复用同一个 `KeySource`。生产走系统凭据管理器，开发用 `TERMHARBOR_KEY_PROVIDER=devfile`。
  但**凭据管理器绑在交互登录会话上**，MCP 宿主常把子进程起成服务/计划任务，读不到
  （`ERROR_NO_SUCH_LOGON_SESSION`）。0.1.26 起应用每次正常启动都会写一份
  `crypto::mirror`（Windows 用 DPAPI 绑到用户主密钥），MCP 优先读它、读不到才回退钥匙串。
  用户零操作：装完打开一次应用即可。宿主必须跑在**同一个 Windows 账号**下。
- **发布**：主程序自带 `--mcp` 子命令（`termharbor.exe --mcp`），**不初始化 Tauri**，
  所以用户装完就够了，不需要单独分发第二个 exe —— 也绕开了 NSIS 只打主二进制的限制。
  独立的 `termharbor-mcp.exe` 保留作排障用途，两者跑同一份 `mcp::serve_stdio()`。
  > 已实测：release 是 windows 子系统、自己不分配控制台，但宿主用管道接的
  > stdin/stdout 照样能读写，协议收发正常。
  可后置：安装器里加一步"是否注册到 MCP 宿主"。

| 1 | 骨架：新二进制 + JSON-RPC 分发 + `initialize`/`tools/list` + 单测 | 1 人日 | ✅ 已完成（未发版，随下次发版） |
| 2 | `list_connections` + `sftp_list`（最小闭环，能连上并列出） | 1–2 人日 | ✅ 已完成（0.1.17） |
| 3 | `read_file` + `server_facts` + `load_snapshot` | 1–2 人日 | ✅ `load_snapshot` 0.1.24；`sftp_read` 0.1.28 |
| 4 | 配置文件 + 审计日志 + 文档（宿主怎么配） | 1 人日 | ✅ 已完成（0.1.27，含 GUI 设置页与 exec 档） |
| 5 | M8-2 `exec` 三道闸门 | 1.5–2 周 | ✅ 已完成（0.1.27） |
| 6 | 文件读写与互传（`sftp_read`/`write`/`upload`/`download`/`mkdir`/`rename`） | 1 人日 | ✅ 已完成（0.1.28） |
| 7 | 凭据类文件默认挡 + 命令密码脱敏 | 0.5 人日 | ✅ 已完成（0.1.29） |

先做 1–2 步就能判断这件事值不值得继续：能列目录、能读一个文件，就说明架构通了。

**第 1 步实际落地的东西**（`src-tauri/src/mcp/` + `src/bin/termharbor-mcp.rs`）：
`jsonrpc`（请求/响应/错误码）、`server`（`initialize` / `ping` / `tools/list` / `tools/call`
分发，通知不回包）、`tools`（三个只读工具的元信息与 JSON Schema）。
工具实现本身故意留空（返回 `isError: true` 的说明文字），只验证协议链路。
踩到并修掉的两个真问题：`input_schema` 忘了加 `camelCase` 会序列化成 `input_schema`
（宿主找不到 schema）；错误响应用结构体展开拼装会多出 `"result":null`（规范要求互斥）。
两条都有测试钉住。

**第 2 步落地的东西**（0.1.17）：`mcp/context.rs` 两次懒加载（库、密钥）+
`AppPaths::resolve_headless()`（不依赖 Tauri 的路径解析，和 GUI 共用同一个 `under()`）；
`list_connections` 读库但**不碰密文字段**，`sftp_list` 复用 `prepare_probe` 建连接、
列完立刻断开。密钥确实做到了"用到才取"：只列连接不会触发凭据管理器。

**第 4 步（0.1.27）**：白名单、审计、执行档、GUI 设置页一起落地。
- `mcp/config.rs`：fail-closed，按 (mtime, len) 热加载，原子写；
  未开放的连接在错误信息里表现得"不存在"，避免 agent 枚举库里的机器
- `mcp/audit.rs`：JSONL 只追加，成功与拒绝都记，参数过 `redact()`；
  `clientInfo` 只作追溯，不参与放行
- `mcp/exec.rs`：复合字符先于白名单匹配，token 序列前缀（不是字符串前缀）
- `ssh/exec.rs` 的超时/输出上限参数化，MCP 侧按配置给
- 设置页「MCP 接入」：连接勾选、工具复选、路径增删、命令模板、被拒请求一键允许、
  复制宿主配置；自动保存，不重启宿主。另给「一键开放只读」降低升级落差
- 实时 GUI 确认**没有做**：那需要 GUI 常驻 + IPC，与 MCP 独立运行冲突；
  改成配置时授权 + 拒绝请求入口，效果等价且架构不变

**第 3 步（0.1.24）**：`load_snapshot` 接上真实采集 —— 复用 `monitor::load::SAMPLE_COMMAND`
（一条 exec 通道、内部 sleep 采两帧算速率），数字和界面看板完全一致。

**第 6 步（0.1.28）：从「只读三工具」改成「能干活」，同时纠正授权心智模型。**

0.1.27 的模型是逐项白名单：勾了连接还要勾工具、加路径、加命令，三步缺一步就什么都干不了。
这是把"一个 SSH 连接"拆成十几个碎片再让人逐个点回去 —— 权限模型比使用场景还复杂，
结果就是功能事实上不可用。0.1.28 反过来：

- **`enabled: true` = 这台机器的全部能力**。`tools` / `paths` / `exec.allow` 三个列表
  **留空 = 不限**，填了才变成收窄。旧配置里的非空列表继续按「只允许这些」解释，语义不变，
  不需要迁移
- 唯一保留的默认限制是**引号外的复合符号**（`; && | > <` `$()` 反引号 `()`、换行）。
  它不是权限门槛，而是「一次调用只做一件事」的契约 —— agent 要多步就多调几次。
  **0.1.30 修了这里的误伤**：旧实现无脑扫字符，`curl -w '%{http_code}'`、
  `curl 'http://h/?a=1&b=2'`、`grep -E 'a|b'`、`awk '{print $1}'` 全被当成复合命令，
  而拒绝文案又说"去设置里放开"——设置里根本没有这个开关，用户只能白翻一圈。
  现在按 shell 引号语义判定（单引号全字面、双引号内仍拦 `$()` 与反引号、未闭合直接拒），
  且拒绝文案会指出具体符号并说明「这是写法问题」。
- 超时默认 10s → 60s、硬上限 30s → 300s。装包、跑部署脚本本来就是这个量级，
  30 秒上限会让"能用"变成"总超时"
- 新增 `sftp_read` / `sftp_write` / `sftp_upload` / `sftp_download` / `sftp_mkdir` / `sftp_rename`，
  全部薄封装现有的 `sftp` 层（`transfer::upload/download` 自带 `.part` + 改名，
  失败不会留半截文件）
- 仍不让步的两条：连接级 `enabled` 必须显式勾选（升级不能把用户已有的服务器静默交出去）；
  应用自己的数据目录（加密凭据、主机指纹、快照）既不能当上传源，也不能当下载目标

设置页跟着改成「勾选即授权」：勾完就显示一行摘要（全部工具 · 任意路径 · 任意单条命令），
需要收紧时展开「细化权限」。三处都是留空 = 不限，不再有"先猜该填什么"的空白页。

**第 7 步（0.1.29）：补两条零配置成本的后置防线。**

0.1.28 把权限一口气放开之后，有两处漏洞是「不用用户配置就能堵上」的，所以单独做掉：

- **凭据类文件默认挡**（`config::secret_path_reason`）。不限路径 ≠ 什么都能读：
  `~/.ssh/id_rsa` 拿到手就能登别的机器，`authorized_keys` 一写就是永久后门，
  `/etc/shadow` 是离线爆破的原料。这四类（SSH 密钥 / 系统提权 / 数据库仓库凭据 /
  云容器凭据）默认拒绝，`allowSecretFiles` 一台机器一个开关才放开。
  判据是「读到它等于拿到更大访问权」，所以**刻意不收** `*.pem` / `*.key` / `.env` /
  `.bash_history` / `~/.ssh/config` —— 误伤比漏挡更伤用户耐心
- **`redact_command`**（`redact.rs`）。审计记命令原文是为了「允许这条」能用，
  但 `mysql -pXXX` 这种短选项密码 `redact` 认不出来。处理方式是按**程序名限定**，
  只对 `mysql`/`mysqldump`/`mariadb`/`redis-cli` 这几个确定用短选项传密码的程序生效 ——
  不猜，因为 `mkdir -p`、`ssh -p 22`、`ps -p 1234` 的 `-p` 都不是密码。
  `--password VALUE`（空格形式）则加进通用 `redact`，靠 `--` 前缀区分于普通英文句子

配套：审计里脱敏过的命令**不给**「允许这条」按钮（服务端也拒），因为脱敏值写进白名单
永远匹配不上真实命令，会变成"看着已允许、实际全被拒"，比直接拒绝更难排查。

**顺带修的路径 bug**：`AppPaths::product_dir` 是 `data_dir.parent()`，也就是 `%APPDATA%`
**本身**，不是 `TermHarbor` 那一层。0.1.28 直接把 `mcp.json` / `audit.jsonl` 写在它下面，
于是两个文件散落在 Roaming 根目录 —— README 写的 `%APPDATA%\TermHarbor\` 一直是对的，
实现少拼了一层。和 0.1.16 的快照目录 bug 是同一类。

现在统一走 `mcp::data_dir()`（`product_dir.join(PRODUCT_FOLDER)`），并做一次性搬迁：
旧位置有、新位置没有才搬；两边都有以新位置为准；**配置搬不动就整体退回旧目录** ——
宁可继续用旧位置，也不能让白名单"凭空消失"变成全关，那会让用户以为配置被清了。
`"TermHarbor"` 这个字面量同时被快照和 MCP 用到，提到 `state::PRODUCT_FOLDER` 只留一份。
MCP 没有长期会话，所以新增 `ssh::exec::exec_on_fresh_connection`：建临时连接 → 跑一条
→ 断开，每次多一次握手（实测 262ms 全链路），换来不用维护会话池。
顺手把探活的各种失败分支（指纹未确认/已变更/证书）折成一句能照做的中文提示 ——
MCP 没有弹窗渠道，只能要求用户先去 GUI 确认一次指纹。

**顺带修掉一个数据安全 bug**（第 2 步写测试时发现的）：`AppPaths` 把 `backup::dir()`
喂成了 `app_data_dir`，而它期望的是**产品根目录**，于是快照实际落在
`%APPDATA%\com.termharbor.app\TermHarbor\backups` —— 正好在卸载器
`RmDir /r "$APPDATA\${BUNDLEID}"` 的删除路径里，所谓"安全网"等于没有。
修法：`under()` 里改成从 `data_dir.parent()` 算，并加一次性搬迁
（`backup::migrate_legacy`，只搬 `termharbor-*.db`，丢掉过期 WAL）。
