# 数据库面板增强 — 开发计划

> 制定日期：2026-11-18
> 前置版本：0.3.5（数据库面板首个可用版本，提交 `1653a16`）
> 目标：把"偶尔查一下"升级为"能顺手写 SQL"，补上免密、表清单、语法高亮与上下文补全。

---

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 总工作量 | 约 **5 个批次 / 5 天**（单人，含自测） |
| 批次划分 | P0 免密 → P1 schema 缓存 → P2 表清单 → P3 CM6 编辑器 → P4 补全接线 → P5 语句级执行 |
| 关键路径 | P1 → P4（补全质量取决于 schema 准不准），P3 → P4 |
| 最大风险 | ① CM6 明暗主题遗漏 ② schema 体积超上限 ③ `@marimo-team/codemirror-sql` 还是 0.3.0 |
| 每批结束都要 | `cargo fmt` + `clippy -D warnings` + `cargo test` + `vitest` + **打一次包**，不攒到最后 |

**一句话策略**：先把"数据来源"（schema）和"零配置体验"（免密）做对，再换编辑器。反过来会做出一个补全列表全是空的花架子。

## 1. 现状

已具备（0.3.5）：

- 终端页右侧「数据库」面板，`sidePanel === "db"`
- 走 SSH 通道调远端 `mysql`，密码经 `--defaults-extra-file=/dev/stdin` 送入
- 账号密文存 `db_accounts`（迁移 007）
- 结果按 `--batch` 制表符解析，表格只渲染前 500 行

已知欠缺：

| # | 问题 | 影响 |
|---|---|---|
| 1 | 密码必填 | root 若是 `auth_socket` 则无法使用，且逼用户设密码 |
| 2 | 没有表/列信息 | 不记得表名就只能瞎猜，也不知道有哪些列 |
| 3 | 输入框是裸 `textarea` | 无高亮、无补全、undo 弱、长 SQL 难改 |
| 4 | 只能整段执行 | 写了三条语句时无法只跑其中一条 |

## 3. 各批次明细

### P0 免密支持

**目标**：`root@localhost` 是 `auth_socket` 时，面板不填密码也能查；填了密码照旧。

**改动**

- `src-tauri/src/dbcli/mod.rs::build_option_file`：`password` 为空时**不写** `password=` 行，让 mysql 走 socket 认证。
- `src-tauri/src/commands/db.rs::db_account_save`：去掉"密码不能为空"的校验，改为只校验用户名。
- `src/pages/DbPanel.tsx`：密码框 placeholder 改成「留空则用服务器的 socket 认证（root 免密）」。
- 补测试：密码空 → option file 里不含 `password=`。

**验收**

1. 服务器上 `ALTER USER 'root'@'localhost' IDENTIFIED WITH auth_socket;`
2. 面板密码留空保存，执行 `select 1` 有结果。
3. 端点：填错密码时仍然报 `ERROR 1045`，不能静默降级。

**注意**：密码留空不是"跳过认证"，只是不传这个字段。如果目标账号是 `caching_sha2_password` 且密码非空，会得到 1045，这是正确答案。

---

### P1 schema 拉取与缓存

**目标**：拿到当前库的表和列，供补全与表清单使用。

**改动**

- 新增 `src-tauri/src/dbcli/schema.rs`：
  - `fetch(conn, account, password) -> AppResult<SchemaSnapshot>`
  - SQL：
    ```sql
    select table_name, column_name
    from information_schema.columns
    where table_schema = database()
    order by table_name, ordinal_position
    ```
    用 `database()` 取默认库，省一个参数。**默认库为空时直接返回空快照**，前端提示"先配默认库"。
  - 逐行 fold 成 `{ tables: [{ name, columns: [..] }] }`
- 在 `DbLinks` 旁边加 `SchemaCache`：`HashMap<connectionId, { at_ms, database, snapshot }>`，TTL 10 分钟。
- 命令 `db_schema(connection_id, refresh: bool)`：命中缓存直接返回，`refresh=true` 强制重拉。
- DTO 序列化到前端，单库几百表约几十 KB。

**为什么不合并成一行一表**

`group_concat` 受 `group_concat_max_len` 限制（默认 1024 字节），列多的表会被静默截断。为了不截断就得先 `set session`，而我们的解析器只认第一个结果集，多语句会串。两列平铺虽然行数多，但 1MB 上限足够放下几千张表。

**验收**

1. `db_schema` 返回的表数量与 `select count(*) from information_schema.tables where table_schema=database()` 一致。
2. 第二次调用时间明显短于第一次（命中缓存）。
3. `refresh=true` 后能拿到新建的表。

**风险**：库特别大时会顶到 1MB。应对：超过时只返回表名 + 前 50 列，并在 DTO 上带 `truncated` 标记。

### P2 表清单浏览

**目标**：不用记表名。

**改动**

- `DbPanel` 在编辑区上方加一排可折叠的表清单（不是侧边树，面板本来就窄）。
- 点击表名 → 在编辑器插入 `select * from 库.表 limit 20`（替换当前内容，带上 `limit` 避免一上来就拉全表）。
- 顶部加「刷新表结构」按钮，调 `db_schema(refresh: true)`。

**验收**

1. 打开面板能列出当前库的表，数量和 P1 一致。
2. 点一张表，编辑器内容变成可执行语句，直接 Ctrl+Enter 有结果。
3. 新建一张表后点刷新，列表里出现。

---

### P3 换成 CodeMirror 6

**目标**：把 `textarea` 换成 CM6，拿到高亮、撤销、搜索、选区。

**改动**

- 依赖（**动态 import**，不压首屏）：
  - `codemirror`、`@codemirror/view`、`@codemirror/state`
  - `@codemirror/lang-sql`、`@codemirror/theme-one-dark`（或自写暗色）
  - `@codemirror/search`、`@codemirror/commands`
- 新增 `src/components/SqlEditor.tsx`：薄封装，`useRef` + `EditorView`，props 只有 `value / onChange / onRun / theme`。
- `DbPanel` 里 `<textarea>` 换成 `SqlEditor`，用 `React.lazy` + `Suspense` 包住。
- `Ctrl/Cmd+Enter` 通过 CM6 的 `keymap` 注册，回调给 `onRun`。
- 主题：把项目令牌映射进 `EditorView.theme`，明暗两套各写一份；补全浮层、光标、选区的配色都要显式给，否则暗色下会漏白。

**验收**

1. 明暗两套截图，编辑器区域无白块、无刺眼默认蓝。
2. 输入时无卡顿；中文输入法正常（重点测中文列名）。
3. `npm run build` 后主 chunk 体积**不增长**（确认拆到独立 chunk）。
4. `Ctrl+Enter` 能执行；`Ctrl+F` 能搜索。

**风险**：CM6 的样式体系独立于项目 CSS，容易出现"左边对齐了、浮层没对齐"。这一批要留出整块时间做视觉，不能顺带完成。

---

### P4 补全接线

**目标**：关键字、库、表、列都能补，且 `from users u` 后敲 `u.` 只出 users 的列。

**改动**

- `sql({ dialect: MySQL, schema })`：schema 由 P1 的数据转成 `{ 表名: [列名] }`。
- `@marimo-team/codemirror-sql` 的 `aliasColumnCompletionSource` + `cteCompletionSource` + `unqualifiedColumnCompletionSource`，从 DTO 转换。
- 补全触发：输入时自动 + `Ctrl+Space` 手动。
- schema 变化（P1 刷新）后要能看到新表——用 `Compartment` 重配 extension，不要重建 `EditorView`（会丢撤销历史）。

**验收**

1. `select * from ` 能列出当前库的表。
2. `select * from sgcc_ops.某表 u where u.` 只列该表的列。
3. 打错表名时标黄（语义 lint）。
4. 切换明暗后补全浮层配色跟随。

**风险**：`@marimo-team/codemirror-sql` 版本 0.3.0，API 可能变。对策：把它的调用收在 `src/lib/sqlComplete.ts` 一个文件里，出问题只改这一处。

---

### P5 语句级执行

**目标**：写多条语句时，只跑当前光标所在的那条；有选区就跑选区。

**改动**

- 新增 `src/lib/sqlSplit.ts`：按分号切分，**跳过字符串字面量与反引号标识符里的分号**，返回 `{ from, to, text }[]`。
- `SqlEditor` 暴露 `getSelectionOrStatement()`：有选区返回选区，否则按光标位置找到所属语句。
- 纯函数配单测：单条、多条、字符串含分号、注释含分号、末尾无分号。

**验收**

1. 三条语句里光标停在第二条，只执行第二条。
2. `select ';' as x` 不会被切成两条。
3. 有选区时只执行选区。

## 4. 明确不做

| 不做 | 理由 |
|---|---|
| 行内编辑结果集 | 要处理主键识别、乐观锁、批量提交，成本是前面所有批次之和 |
| 表结构设计器 / ER 图 | 属于另一个产品方向 |
| 多数据库类型（PostgreSQL 等） | 现在只有 MySQL 的实际需求；schema 查询要重写一套 |
| 结果集虚拟滚动 | 500 行上限够用，等真的卡了再做 |
| Vim / Emacs 键位 | 可以后加，但没必要进首批 |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| CM6 主题遗漏暗色样式 | 界面割裂，返工 | P3 单独留整天做视觉，明暗截图必须都过 |
| schema 体积顶到 1MB | 大库下补全失效 | DTO 带 `truncated`，超限时降级成"只补表名" |
| marimo 扩展 0.3.0 变更 | 别名解析失效 | 调用点收在单个文件，降级方案是退回 `lang-sql` 自带的 schema 补全 |
| 动态 import 影响 UiPreview 截图 | 截图脚本要等更久 | `shot-db.mjs` 的等待时间调长，或加 `waitFor` 轮询到元素出现 |
| 补全噪音 | 比不补更烦 | 只补当前库；列名补全必须带表上下文，不做全局列名兜底 |

## 6. 关键技术决策（沿用，不在本计划内变更）

- **不引 Rust MySQL 驱动**：继续借 SSH 跑远端 `mysql`。`sqlx` 的 `caching_sha2` fast-auth 有 bug（issue #4244）且 `rsa` crate 有未修复漏洞，真要用驱动应选 `mysql_async`。
- **密码走 stdin**，不用 `MYSQL_PWD` / `-p`，避免出现在进程命令行与错误信息里。
- **文本协议的两个固有限制**继续保留：`NULL` 与字符串 `"NULL"` 不可区分；二进制字段要用 `HEX()`。
